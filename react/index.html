JavaScript to revise

These twelve concepts cover almost all the JavaScript that React code uses. Each builds on the one before. Tick one off when it feels familiar.

1let and const

const cannot be reassigned; let can. Both are block-scoped, unlike var. Use const by default. The contents of a const object or array can still be changed; only the variable itself cannot be reassigned.

const name = 'Konark';
let count = 0;
count = count + 1;

In React: almost everything is const, including components and state.

Read more

2Arrow functions

A shorter way to write a function. With one expression, the result is returned without writing return.

const double = (n) => n * 2;
const greet = (name) => {
  return 'Hi ' + name;
};

In React: components, event handlers and callbacks are usually arrow functions.

Read more

3Template literals

Strings in backticks that can hold variables and span lines.

const msg = `Incident ${number} is ${state}`;

In React: building URLs, class names and labels.

Read more

4Destructuring

Pull values out of an object or array into variables in one line.

const { number, priority } = incident;
const [first, second] = list;

In React: reading props, and const [value, setValue] = useState() is array destructuring.

Read more

5Spread and rest (...)

Spread copies the contents of an array or object into a new one. Rest collects the remaining items.

const updated = { ...incident, state: 'Closed' };
const more = [...list, newItem];

In React: you never change state directly; you create a new copy with spread. This is the biggest habit change from AngularJS.

Read more

6Array methods: map, filter, find, reduce

They return a new result instead of changing the original array.

const open = incidents.filter(i => i.active);
const numbers = incidents.map(i => i.number);
const one = incidents.find(i => i.sys_id === id);

In React: map replaces ng-repeat for rendering lists; filter drives search and filters.

Read more

7Short conditions: ternary, &&, ?. and ??
const label = isOpen ? 'Open' : 'Closed';
const group = incident.assignment_group?.name;
const title = incident.short_description ?? 'No title';

?. stops safely if something is null or undefined. ?? gives a fallback only for null or undefined.

In React: these replace ng-if and ng-show inside JSX. One difference to know: ng-show hides an element with CSS, while these conditions leave it out of the page completely, like ng-if.

Read more on ?. · Read more on ??

8Modules: import and export

Each file exports what it shares, and other files import it.

// IncidentCard.jsx
export default function IncidentCard() { }

// App.jsx
import IncidentCard from './IncidentCard';

In React: every component lives in its own file and is imported where used.

Read more

9Callbacks and functions as values

A function can be stored in a variable and passed to another function.

const handleClick = () => console.log('clicked');
<button onClick={handleClick}>Save</button>

Pass handleClick, not handleClick(). With brackets it runs immediately.

In React: this is how a child component tells its parent that something happened.

Read more

10Promises and async/await

A promise is a value that arrives later. await pauses inside an async function until it arrives.

async function load() {
  try {
    const res = await fetch(url);
    const data = await res.json();
    return data.result;
  } catch (err) {
    console.error(err);
  }
}

In React: all data loading. It replaces the .then() on c.server.get().

Read more

11fetch

The built-in way to call a REST API. It returns a promise.

const res = await fetch(
  '/api/now/table/incident?sysparm_limit=10',
  { headers: { 'Accept': 'application/json' } }
);

fetch does not throw on a 404 or 500; check res.ok yourself.

On a ServiceNow React page, add the session token to the headers. ServiceNow's SDK guide requires it on every call:

headers: {
  'Accept': 'application/json',
  'X-UserToken': window.g_ck
}

In React: calling the Table API or a Scripted REST API.

Read more

12Closures

A function remembers the variables from the place it was created.

function makeCounter() {
  let count = 0;
  return () => ++count;
}

In React: this explains why a handler sometimes sees an old state value. You only need the idea, not the theory.

Read more

Things you can stop worrying about

  • this and .bind(): function components do not use them.
  • var and hoisting: use const and let.
  • Prototypes and classes: rarely needed in modern React.
  • jQuery-style DOM access: React updates the page for you.

Project: Incident Triage Board

A small scoped app on a Personal Developer Instance whose UI is a React page. It covers the pieces an interviewer will ask about: components, state, data fetching, routing and the SDK workflow.

What it does

  • Shows open incidents as cards in columns by state (New, In Progress, On Hold).
  • Filters by priority and assignment group, with a search box.
  • Opens a detail view at its own URL, such as ?view=detail&id=INC0010001.
  • Lets the user assign to themselves, change state and add a work note.
  • Shows a count of breached or high-priority incidents at the top.

Where React fits in ServiceNow

Service Portal widgets are still AngularJS. React comes in through the ServiceNow SDK and ServiceNow IDE, where you build a scoped app in source code and its UI is a React page. So the job skill is "React plus the ServiceNow SDK", not "React widgets".

Service Portal

AngularJS widgets

Your current skill stays valid. ServiceNow maintains its own AngularJS version.

ServiceNow SDK / IDE apps

React, defined through the Fluent UI Page API

The new skill to learn. This plan targets it.

UI Builder / Workspaces

Next Experience components

ServiceNow's own framework. Not React, but the component and state thinking carries over.

Five platform facts

  • ServiceNow's docs label UI development with React an experimental feature, so expect details to change between releases.
  • Normal path-based routing is not available. ServiceNow's two sources disagree on the alternative: the product docs say only hash routing is supported, while the SDK's own guide says to use URL query parameters such as ?view=details&id=123, and not hash routing or React Router. Follow the pattern in the template you scaffold.
  • No server-side rendering and no React server components, so skip Next.js entirely.
  • The build uses Rollup, and CSS modules are not supported.
  • The SDK guide pins React 18.2 and writes components in TypeScript (.tsx), while the docs example uses plain .jsx. The docs say both are supported.

Sources: ServiceNow docs, SDK UI page guide

The React page talks to the instance over REST, mainly the Table API. ServiceNow's SDK guide requires every call to send the X-UserToken header with the value of window.g_ck. ServiceNow also ships a React component library (@servicenow/react-components) with ready-made record lists and forms, which that guide prefers over hand-built ones. Your server-side knowledge of GlideRecord, ACLs and Script Includes carries over unchanged.

What to skip for now

Common in React courses but not needed for ServiceNow work, so leave them until a job asks for them.

  • Next.js, server components and server-side rendering (not supported on the platform)
  • Redux and other state libraries (useState plus Context is enough at this size)
  • Class components and lifecycle methods
  • Webpack or Rollup configuration (the SDK template handles the build)
  • Advanced TypeScript such as generics and utility types
  • Deep CSS frameworks; plain CSS imported in code is enough

How to talk about it in interviews

Lead with the combination, since few candidates have both: five years of platform depth plus hands-on React through the SDK.

  • Explain where React fits and where it does not, using the three cards at the top of this tab.
  • Walk through the project: scaffold, Fluent UiPage, build, install, REST calls.
  • Name the limits (no path-based routing, no SSR, experimental status) to show you have actually used it.
  • Compare a widget and a React component you built, and say what one-way data flow changed.
